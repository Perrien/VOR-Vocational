# V0.1 stable core

Status: **APPROVED 2026-09-17**

## Context

V0.1 makes the current app safe to change without changing what the player sees or does. It adds
tests for the pure navigation core, then puts the existing source and bundled content in a compact
layout that V0.2 can build on.

The app is a single filesystem-synchronized macOS target. `Xcode Proj/VOR Vocational.xcodeproj/project.pbxproj:14`
(`isa = PBXFileSystemSynchronizedRootGroup`) attaches the `VOR Vocational` source folder to the
`VOR Vocational` target at `:52`. Source membership comes from that folder; no XCTest target exists
yet.

`Xcode Proj/VOR Vocational/Model/VORVocationalApp.swift:10` (`@main`) creates `ContentView`, and
`Xcode Proj/VOR Vocational/Model/ContentView.swift:12` (`MapView()`) makes the current map the whole
window. `Xcode Proj/VOR Vocational/MapView.swift:114` (`PlaneControlView(...)`) and `:120`
(`NavRadioView(...)`) are the existing lower control surfaces. They remain unchanged in V0.1.

The pure core is already separate from SwiftUI. `Xcode Proj/VOR Vocational/Simulation/VORNavigation.swift:7`
(`enum VORNavigation`), `Simulation/FlightPhysics.swift:6` (`enum FlightPhysics`), and
`Simulation/PositionChallenge.swift:7` (`enum PositionChallenge`) depend on points and models, not
views. `Model/Models.swift:215` (`struct CDIReading`) supplies the CDI result they use.

## Approach

Create the test bundle in Xcode, add one core test source file, then use the Xcode project navigator
to create and populate the final folders. The existing filesystem-synchronized target picks up files
from the app folder, so no hand edits to `project.pbxproj` are permitted. Do not alter any Swift
declaration, resource filename, JSON content, or view layout while moving files.

### 1. Test bundle: `Xcode Proj/VORVocationalTests/NavigationCoreTests.swift`

Create the `VORVocationalTests` unit-test bundle through Xcode's target template. Set its tested host
to `VOR Vocational`, use Swift, and add it to the Test action of the shared `VOR Vocational` scheme.
Its test source imports `XCTest`, `CoreGraphics`, and `@testable import VOR_Vocational`.

The suite has these test methods and assertions:

- Angle normalization: `0` and `360` return `0`, `190` returns `-170`, `-190` returns `170`, `540` returns `180`, and `-540` returns `-180`.
- CDI on the selected north/south line: with station `(0, 0)`, OBS `0`, and CDI maximum `10`, plane `(0, -10)` reports `.from` and `0`; plane `(0, 10)` reports `.to` and `0`.
- CDI needle direction: plane `(10, -10)` reports `.from` and `-1`; plane `(-10, -10)` reports `.from` and `1`.
- Map distance: `(0, 0)` to `(30, 40)` at `10` pixels per NM is `5`; zero pixels per NM is infinity. Normalized `(0, 0)` to `(0.06, 0.08)` on a `500` NM by `500` NM chart is `50` NM.
- Station lookup: a constructed station with identifier `CTR` is returned for `" ctr "`; an empty identifier returns `nil`.
- Flight advance: `(50, 50)`, heading `0`, `120` knots, `30` seconds, and `10` pixels per NM becomes `(50, 40)`; heading `90` becomes `(60, 50)`; a path past a `100` by `100` bound clamps at its edge; nonpositive speed and nonpositive pixels per NM do not move the point.
- Position challenge: scoring `(0, 0)` against `(30, 40)` at `10` pixels per NM returns the original points and `5` NM error. No stations with `maxAttempts: 0` returns normalized center `(0.5, 0.5)`. A target requested with `minInRangeStations: 0` stays in the default `0.1...0.9` inset on both axes.
- Service volumes: high, low, and terminal ranges are `100`, `40`, and `25` NM.

### 2. App source: `Xcode Proj/VOR Vocational/App/`

`Model/ContentView.swift` to `App/ContentView.swift`. Their source stays byte-for-byte equivalent:

### 3. Domain source: `Xcode Proj/VOR Vocational/Domain/`

Move `Model/Models.swift` to `Domain/Models.swift`, `Simulation/VORNavigation.swift` to
`Domain/Navigation/VORNavigation.swift`, `Simulation/FlightPhysics.swift` to
`Domain/Simulation/FlightPhysics.swift`, and `Simulation/PositionChallenge.swift` to
`Domain/Simulation/PositionChallenge.swift`.

The move retains all type names and access levels. In particular, keep
`VORNavigation.cdiReading` at current `VORNavigation.swift:19`, `FlightPhysics.advance` at current
`FlightPhysics.swift:11`, and `PositionChallenge.randomTarget` at current
`PositionChallenge.swift:32` unchanged. The new test bundle exercises these exact methods.

### 4. Feature source: `Xcode Proj/VOR Vocational/Features/`

Move `PlaneControls.swift` to `Features/Flight/PlaneControls.swift`, `MapView.swift` to
`Features/Map/MapView.swift`, and `OverlayViews.swift` to `Features/Map/OverlayViews.swift`.

`MapView` must keep its current state defaults, including `speedKnots: 120` at current
`MapView.swift:40`, `isFlying: false` at `:41`, one-times zoom at `:49`, and the `350` point lower
panel at `:68`. The lower controls retain the current `NAV1` and `NAV2` text fields at
`PlaneControls.swift:310` and `:318`, and the map sidebar keeps its current layer controls at
`MapView.swift:578`.

### 5. Bundled content: `Xcode Proj/VOR Vocational/Content/`

Move `Assets.xcassets`, `JSON Data/Airports.json`, `JSON Data/SightseeingRegions.json`, and
`JSON Data/VORStations.json` into `Content/`, preserving each basename and contents. The loaders use
the basenames `VORStations`, `Airports`, and `SightseeingRegions` in `Models.swift:84`, `:129`, and
`:200`; they must keep finding those resources after the move.
